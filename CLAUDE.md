# CLAUDE.md

Guidance for Claude Code in this repository: a buildable source for **Stryker's Run (Enhanced)**
(Superior Software, 1986; Chris Roberts and Philip Meller, graphics Nick Elms, music Martin
Galway) for the BBC Master 128, made from an annotated disassembly so it can be optimised.
`PLAN.md` is what is left to do, `docs/done.md` what has landed, `docs/decisions.md` the record
of every agreed decision, `BUGS.md` the bug log. The method is beeb-port-kit's (`C:\Users\khcon\OneDrive\BEEB\Repos\beeb-port-kit`,
`PORTING.md`); its skills are in `.claude/skills/`.

## The rules

- **The original is the specification.** Step 1 rebuilds the game byte for byte; step 2 changes
  how it runs, never what it plays like, unless a decision says otherwise.
- **Deviations are agreed before they are built and written down after**, as numbered entries in
  `docs/decisions.md`.
- **Measure, do not recall.** Every timing number says what it was measured on and when.
- **Verify against the reference, not the screenshot.** `tools/compare.py` for bytes; RAM and
  bank dumps at equal game state for behaviour.

## Target

| | |
|---|---|
| Machine | BBC Master 128 (65SC12, four sideways RAM banks 4-7). The enhanced version needs both |
| Reference | The Stairway to Hell disc, `reference/sth/StrykersRun.ssd` (decision 1): files `MGAME`, `DATA1`-`DATA4`, `SCREEN`, `SRRUN` |
| Disc | Enhanced version only (decision 3): `!BOOT` (stamp, `*TV255,1`, `*FX200,3`) -> `SRRUN` -> `SCREEN`, then `DATA1`-`4` into banks 4-7, then `MGAME` |

## Build

```powershell
.\build.ps1             # build/strykers.ssd (not compared: step 2's code differs from the reference)
.\build.ps1 -Compare    # then tools/compare.py against the reference (-NoCompare: accepted, the default)
.\build.ps1 -Release
```

Step 1's byte-identical source is the tag `step1-identical`; `-Compare` checks a build against the reference.
The `Makefile` is the same build for POSIX (`make`, `make release`, `make SHIFT=256 SHIFTEND=1
DEFINES=DEBUG_LIVES`; comparing is off unless `COMPARE=1`) and makes the same images, byte for
byte: a change to the pipeline lands in both. `make original` builds the tag's source into
`build/strykers-original.ssd`. Milestones get tags (`step2-layerN` as each layer closes; README.md).
Baron 0.5.3 (`bin\baron.exe`, gitignored; built from `C:\Users\khcon\OneDrive\BEEB\Repos\baron`,
decision 2). One assembly, `src/main.6502`, so the game and the banks share one symbol table.
`build/strykers.lst` is the listing, `build/strykers.symbols.json` the symbol dump: take
addresses from there (`python tools/listing.py symbols build/strykers.symbols.json NAME`).
`build_stamp.py` stamps the last commit's time (`+` if the tree is dirty) into `INFO` and `!BOOT`.

## Source (`src/`)

| File | Contents |
|---|---|
| `main.6502` | the disc: one `SECTION` per file, `MGAME`'s copy-down stub |
| `game.6502` | the game, assembled at `&0E00`; the three blocks it copies down at start-up (`&4000`->`&0004`, `&4200`->`&0400`, `&4600`->`&0880`) are rephased nested sections |
| `bank4.6502`..`bank7.6502` | sideways RAM: `DATA1` (bank 4), `DATA2` (bank 5, from `&8400`: title, high scores, music), `DATA3` (bank 6), `DATA4` (bank 7) |
| `title.6502`, `title_data.6502` | `SCREEN`, the loading picture (scope `title`) |
| `loader.6502` | `SRRUN`, `!BOOT`, `INFO` |
| `zp.6502` | zero-page names (several per address: the game reuses zero page) and fixed workspace |
| `os.6502` | MOS calls, vectors, hardware registers |
| `lib/boot_stamp.6502` | the kit's stamp macros |
| `render.6502` | step 2: the renderer (sideways bank 4, from `&9000`): per-screen records, the edge column history, masked sprites over save blocks, the double buffer |
| `sprite_andy.6502`, `sprite_straight.6502`, `sprite_columns.6502` | GENERATED by `tools/sprites.py` (`straight`, `emit`) from the layer-2 build's run-length sprites: the movers' straight sprites (ANDY, bank 4) and column counts |
| `lib/sfx50.6502`, `sfx_data.6502` | step 2 layer 3: the 50 Hz sound effect driver (reusable: ramps, requests by chip channel) and the game's effects, GENERATED by `tools/sfx50.py` (decision 25) |
| `lib/keydown.6502` | the kit's `keydown_int`, forked (step 2 layer 1): the keyboard read straight off the System VIA |
| `font.6502`, `lives_digits.6502` | the in-game font (placed by BUGS #2's rule); the lives digit's bytes, GENERATED by `tools/livesdigits.py src/font.6502 src/lives_digits.6502` |
| `render_bss.6502`, `render_bss_zero.6502` | the renderer's variables, in its workspace (not saved), and their zeroing at start-up (decision 32) |
| `render_zp.6502`, `prebuild.6502` | bank 4 under ANDY (ROMSEL `&04` only): the renderer's save and restore of the game's zero page; the next scroll column built in the wait for the flip (RAM for cycles item 1) |
| `compiled_table.6502`, `compiled_bank5/6/7.6502`, `compiled_hazel_a/b.6502` | GENERATED by `tools/compiled.py`: the player's 14 running sprite parts as code, and the table `compiled_part` indexes (`ck_index`) |
| `music.6502`, `music_packed.6502`, `lib/zx02depack.6502` | the front end's tunes (source, not assembled); them packed, GENERATED by `tools/packmusic.py`; the kit's ZX02 depacker, forked |

`game.6502` and `bank*.6502` were generated once by `tools/disasm2baron.py` from
`reference/strykers-run-enhanced-disassembly.txt` and are **hand-maintained**: the converter
refuses to overwrite them. Lines beginning `\ ` keep the disassembly's own annotations; `***`
marks code that differs from the standard version. Watch for self-modifying code: the
disassembly's `actually`/`also` notes say what an operand really is.

## Tools

- `tools/compare.py [built.ssd] [reference.ssd]` - every file byte for byte
- `tools/m6502.py FILE LOAD START [END]` - 65SC12 disassembler for poking at binaries
- `tools/listing.py`, `tools/dfs.py`, `tools/jsbeeb_src.mjs` - the kit's
- `tools/disasm2baron.py` - the one-shot converter (audit trail)
- `tools/playscript.mjs` - the scripted game (boot, start, run/fire/jump); `tools/play.mjs DISC` plays it with screenshots
- `tools/lockstep.mjs A B [FRAMES]` - two builds on the same input, first frame whose screen differs
- `tools/tracediff.mjs CONTROL SHIFTED SHIFT [@FRAME]` - the first instruction or screen write that differs, both stopped there (`DUMP=05` shows the bytes at a zero-page pointer)
- `tools/profile.mjs DISC [FROM] [FRAMES]`, `tools/speed.mjs DISC` - passes/s, fields per pass, flat profile; speed with RIGHT held
- `tools/irqprofile.mjs DISC [FROM] [FRAMES]` - every interrupt by the VIA source it serviced, its cycles by MOS subroutine (nesting handled: the MOS's tick re-enables interrupts)
- `tools/frontend.mjs DISC` - title, instructions, define controls, pause, high score entry, toggles, two games: 15 checks, plus the MOS state handed over and back
- `tools/observer.mjs DISC` - observer mode's RIGHT, LEFT and ESCAPE (a key path play never takes: BUGS #11); one of the grind's checks
- `tools/split.mjs DISC FROM FRAMES`, `tools/splitscroll.mjs DISC` - when the palette writes land after vsync, every field / on scrolling fields
- `tools/soundfx.mjs DISC OUT.json` - each sound effect's SN76489 writes, for comparing two builds
- `tools/passlock.mjs CONTROL TEST [PASSES] [SEED] [--screen]` - two builds in step by pass (same keys per pass), game state compared every pass, and the shown screen (`--trace`, `--dump`, `WATCH=` to chase a difference). Layer 2's oracle: build both `-Shift 256 -ShiftEnd` so the ground pattern is fixed
- `tools/shadowaudit.mjs DISC` - what the renderer reads in `&3000-&3FFF` with ACCCON's X bit set, against what play writes there
- `tools/passbench.mjs DISC [DISC2 ...]` - speed on the same game whatever the build's speed (keys by pass, as passlock): compare builds with this, not the frame-timed tools
- `tools/fieldcost.mjs DISC [--hold RIGHT] --out PER.json`, `tools/fieldsim.py PER.json [--report]` - passbench's game by pass:
  logic by group and mover, render by slot and type, what changed and who wrote it; then 50 Hz schedules field by field
  (`docs/step2-layer4-costing.md`)
- `tools/passcost.mjs DISC [FROM] [FRAMES] [--right]`, `tools/passhist.mjs` - a pass's cycles by phase; each pass's work against the bytes it drew
- `tools/helilock.mjs CONTROL TEST [PASSES] [VARIANT]` - two builds in step through a helicopter flight (board, fly, shot down), state and newest frame every pass; passlock's scripts never board one
- `tools/worldcheck.mjs DISC` - the renderer's world position of each record against the mover's x/y (BUGS #7)
- `tools/zplive.mjs DISC` - the zero-page bytes the logic reads first after a render (what `restore_game_zp` must keep)
- `tools/analyse.py report|annotate` - beebgame's static analyses of the build (liveness, known values, ranges,
  register ABIs; `build/dataflow/`): `tools/dataflow/` vendored, `tools/baron_dbg.py` reads a Baron build,
  `tools/dataflow_config.py` and `tools/isr_model.py` describe this game's interrupts (the beeb-dataflow skill)
- `tools/compiled.py LAYER2.ssd src` - the player's running sprite parts as code (`src/compiled_*.6502`), from the layer 2 build's sprites
- `tools/pcprof.mjs`, `tools/pcagg.py`, `tools/pccats.py`, `tools/budgetdata.py` - per-instruction profile by phase, label and job; the cycle budget page's data
- `tools/drawprof.mjs`, `tools/whatif.py`, `tools/colfast.py` - each draw by label and byte kind; costing renderer changes on measured passes
- `tools/grind.py windows|add|queue|apply|revert|gate|run|report`, `tools/grind_config.py` - the micro-optimisation grind (the beeb-micro-grind skill): annotated windows weighted by cycles, the ledger (`docs/grind/`), the proof gate, the serial apply-and-prove run
- `tools/pipesim.py PERPASS.json`, `tools/unlocksim.py PERPASS.json` - measured passes replayed under other loop orders: the logic ahead; the flip at the next vsync
- `tools/packmusic.py` - the front end's tunes packed (ZX02) into `src/music_packed.6502`, checked by unpacking
- `tools/hazelwatch.mjs DISC`, `tools/hazelreach.mjs DISC` - who touches HAZEL after the start; how far the mountain layer reads
- `tools/hang.mjs DISC PASS`, `tools/screendiff.mjs A B PASS` - where a stalled build goes; two builds' screens byte by byte
- `tools/sprites.py stats|emit|straight` - sprite sizes, save block sizes, and the generated sprite sources
- `tools/sfxcapture.mjs DISC OUT [--pairs]` - each sound effect's chip writes by MOS tick; `--pairs`, an effect over another
- `tools/sfx50.py CAPTURE.json OUT.6502 [--show]` - fit 50 Hz ramps (for `src/lib/sfx50.6502`) to captured effects; `--show` prints them against the MOS's
- `tools/worldmap.py [DISC] [--out DIR] [--json F] [--crop LEFT ...] [--observed DIR]` - the whole world from the build's level data
  (`docs/level-format.md`): `world-background.png` (every layer and the ground), `world-objects.png` (movers, helicopters, craft,
  trigger points); `--crop` the 80 columns a view shows. `tools/worldshots.mjs DISC OUT COLUMN ...` - the emulator's screen
  there (observer mode, holding RIGHT; mends `check_for_keypress` in RAM), to compare with `--crop`/`--observed`
- Harnesses must read `&3000-&7FFF` with `{ shadow: false }` (or `true`): the renderer may have the CPU on shadow RAM

## Memory (MGAME, as the reference lays it out)

`&0000-&00FF` zero page, with game code at `&0004-&0077` (the sprite column unpacker; step 2: dead,
its first bytes kept as the ground's, the rest the renderer's variables - decision 34);
`&0300` column buffer; `&0400-&07FF` and `&0880-&095F` copied-down code and data (step 2: and
`&0A20-&0CFF`, `moved_0a20`: `multiply_by_78`, `rows_up` and the level tables, 154 bytes free at its
end, decision 40); `&0E00-&3FFF` code and data; `&4000-&46FF` start-up code (step 2: mostly in the save arena, decision 33), then the screen `&4000-&7FFF` (16K, MODE 2,
hardware-scrolled by the CRTC). Bank 5 `&8000-&83FF` is the player buffer.

Step 2 additions: zero page `&90` (`field_count`), `&92`/`&93` (the PRNG), `&9B` (`drawing`),
`&9C/&9D` (the sprite walk's and the renderer's pointer), `&9E` (`plot_sprite`); `&1F-&75`, the
unpacker's dead body, the renderer's hottest variables (`ren_zp` in `moved_0004`, decision 34;
`&0004-&001E` stay as the ground's bytes, BUGS #1); the renderer's
scratch `&C0-&CD` (given back by `restore_game_zp` only where the logic reads). `&354A-&3FFF` is
the save arena (main and shadow, one per screen), after `player_save` (`&34D5`, 117 bytes a screen:
the compiled kinds' saves, shared by kinds never drawn together); ANDY `&8000-&8FFF` holds 53 sprites, paged in while the renderer draws.
Decision 40 took 1,038 bytes of read-only tables out of the main block and placed what stays by its
reads: the scenery tables, `movers_firing_cooldown`, the unflipped mover sprite addresses, the movers
and projectiles from `&1300` (page-aligned, ASSERTed; `movers_state_end` ends them), the flipped mover
sprite addresses; the code starts at `&14DF`, 1,024 lower than the original's `&18DF`. The keyboard read
(`keydown_int`, `&2F0E`), PRNG, `render_pass` and `pass_start` follow, `compiled_call` (the stub
that pages a compiled kind's bank) after them, and what is free up to `&33FF` is the listing's `SKIP
unused_3400_original` (1,044 bytes on 2026-10-18, after decision 40, from `&2FEC`); everything from `&3400` stays
where the original had it (BUGS #1, #2). The interrupt's variables are below `&3000` (the renderer
draws with ACCCON's X bit set when the target is shadow). Bank 4: the renderer `&9000-`, then its
sprites and tables (below `REN_BASE`, `&B400`, ASSERTed in `src/main.6502`: BUGS #6); workspace
`&B400-&BEFF`, not in the file, with the renderer's variables in the bytes its tables leave
(`src/render_bss.6502`: `&B780`, `&B8C8`, `&B9C8`, `&BC22` after the packed `zp_save`, `&BE80`;
zeroed at start-up by `zero_render_vars`, decision 32); under ANDY, the
prebuild, `save_game_zp`/`restore_game_zp` and `zero_render_vars` (ROMSEL `&04` only). Banks 5-7
end with 8 of the player's compiled sprite kinds (`tools/compiled.py`; each bank's end ASSERTed);
the other 6 are in HAZEL at `&C700-&D8AD`, which the MOS leaves paged in through play (ACCCON's Y
bit); HAZEL `&C300` on is the mountain layer's data (BUGS #9) and stays untouched. Decision 40's HAZEL
tables: `times_78_lo/hi` at `&C000/&C100` (made at start-up), and in `hazel_b` after the kinds
`player_helicopter_types_vertical_speed` .. `player_helicopters_initial_x_high` (`&D905-&D9DA`) and
the mover type tables (`&DA01-&DB86`), read in play only; 121 bytes left under `hazel_b`'s `&DC00` ASSERT. On the disc they
ride in bank 5's music area and the start-up block; `unpack_for_play` copies them in and unpacks the
front end's tunes (`src/music.6502` -> `tools/packmusic.py` -> `src/music_packed.6502`, ZX02) to
`&9300`. The start-up code and the blocks it copies down ride in the save arena's bytes
(`&354A-&3FCD`, decision 33: nothing touches the arena before the first `render_reset`; 50 bytes of it
left as a carrier after decision 40); `hazel_b`
and the packed tunes follow `&4000` to `mgame_end` (`&497A`), so `MGAME` loads to `&547A`, 1,542
bytes under the loading picture at `&5A80` (ASSERTed). Bank 5's `&8000-&83FF` (the player buffer) is free:
masked drawing made it unnecessary.
Bank 5 grows only at its end (its music is page-aligned). In play the game's `irq1_handler` owns
vsync and flips the two screens (main and shadow, both `&4000-&7FFF`); on the front end the MOS
has vsync and only main is used (decisions 14, 23).
