| 7 | 2026-10-16 | **How relocation is proven.** `-D SHIFT=&100` assembles the game a page lower (`&0D00`) and moves each bank's contents a page higher; `-D SHIFT_END=1` is the control, the same padding where it moves nothing, so both discs load in the same time. Rates are rescaled so each object moves at that pass rate's speed per second, in smaller or evenly spaced steps at 50 Hz. (KC) | PLAN.md step 2 |
| 13 | 2026-10-16 | **The original's quirks are fixed** (BUGS.md #1 ground texture, #2 legs sprite overrun), not reproduced. (KC) | PLAN.md step 2 |
| 14 | 2026-10-16 | **In play the game's `irq1_handler` keeps vsync from the MOS; the MOS keeps only System VIA T1, its 100 Hz tick, for the OSWORD 7 sound.** The handler counts fields (`field_count`, `&90`) and acknowledges CA1 itself; on the title, high scores, instructions and define controls the MOS has vsync as before (their music is MOS events, their keys `&EC`, and OSBYTE 19). Switching (`take_irq_for_play`, `give_irq_back`, bank 5) saves and restores the MOS's state: CA2 (keyboard) and CB1 (ADC, unused by the game) are off in play; the keyboard polling state `&0242` is 0 so the tick never scans; bit 1 of the System VIA IRQ mask `&0279` is clear so the MOS cannot take a vsync that arrives while a tick is being chained to it - which the original lost in 12 fields of 1,000 (BUGS #3). Interrupts went from 21.0% to 10.6% of the CPU. The MOS out of the interrupt entirely, with the game's own sound driver (probably 50 Hz), and owning the front end too, are for later. (KC) | `docs/step2-layer1.md`, `src/game.6502`, `src/bank5.6502` |
| 15 | 2026-10-16 | **User VIA T1 (the palette split) is never passed to the MOS**, title included: the MOS recognised no such source and offered it to every paged ROM (service call 5), 1,165 cycles a field. | `irq1_handler` |
| 16 | 2026-10-16 | **The keyboard is read straight from the System VIA** in play: `check_for_keypress` is the kit's `keydown_inkey` (`src/lib/keydown.6502` forks `keydown_int`), same contract, the `keys` table still INKEY numbers so define controls is untouched. Measured on jsbeeb 2.5.0, Master 128: the nine game keys' internal numbers by name (A 65, Z 97, RIGHT 121, LEFT 25, SHIFT 0, DELETE 89, CTRL 1, P 55, ESCAPE 112), and the direct read agreeing with OSBYTE &81 for all 128 key numbers with each held. | `src/game.6502`, `src/lib/keydown.6502` |
| 17 | 2026-10-16 | **A PRNG for the four random numbers the original read from User VIA T2** (helicopter height, soldier crouch, stationary mover, `rnd_skewed_towards_right_of_world`): a 16-bit xorshift (7, 9, 8), state `&92`/`&93`, **seeded `&7A31` at every game start** so a game replays exactly from its input. With the pass locked to vsync, T2 would repeat. The original's values at those sites were near-uniform (measured over 20,000 frames), so the odds are kept. (KC: fixed seed) | `random`, `take_irq_for_play` |
| 18 | 2026-10-16 | **The pass is locked to 2 fields by the field counter**, replacing `wait_for_timer_281a`'s ~1.84-field floor (decision 12): a pass inside its slot waits for the slot's end, one that overruns waits for the next field, so every pass is whole fields and starts at a vsync. `update_movers` no longer runs System VIA T2 as the floor's stopwatch. | `wait_for_timer_281a`, `update_movers` |
| 19 | 2026-10-16 | **`wait_for_vsync_2242` waits on `field_count`, then 176 cycles**: OSBYTE 19 would hang with the MOS kept from vsync, and returned ~170 cycles later than our counter does; the User VIA timers this routine restarts are the raster clock and the palette split, so without the delay the split sat 1.5 scanlines higher on scrolling fields. The delay replaces the original's `LDA #0 : STA usrvia_ier`, which changed nothing. Measured: T1 re-armed 420-430 cycles after vsync in both builds. | `wait_for_vsync_2242` |
| 20 | 2026-10-16 | **The soldier jump (BUGS #4) is fixed, not emulated**: `unplot_and_move_mover` moves a mover from its own x. 81 of 8,495 moves jumped 1-6 columns in the original. (KC) | `src/game.6502` |
| 21 | 2026-10-16 | **Layer 2 draws from per-screen records** (KC, over replaying each pass's draws): the logic no longer draws; a renderer in bank 4 keeps what each screen shows per mover slot and brings the hidden screen up to date at the end of a pass. The logic's plot calls walk the sprite as the plotter would and the renderer restores the game's zero page, so the logic sees what it saw (pass lockstep: state identical over 42,000 passes). One visible difference from the original: the screen shows the state at the end of the pass, where the original's own draw calls now and then lagged it - an explosion or bullet a pass early or late, 8 passes in 42,000. | `docs/step2-layer2.md`, `src/render.6502` |
| 22 | 2026-10-16 | **The palette split is steady**: set only by the vsync interrupt. The original dropped it ~2.5 lines on fields where its raster wait re-armed User VIA T1; with the waits gone it does not (recolours at most a few pixels: the lines between are almost all other colours). Supersedes decision 19, whose delay is gone. (KC) | `irq1_handler`, `wait_for_vsync_2242` |
| 23 | 2026-10-16 | **Two screens at `&4000-&7FFF`, main and shadow**, shown in turn by the vsync interrupt (R12/R13 and ACCCON's D bit) at the field the pass lock picks; ACCCON's X bit while the renderer draws into shadow, so shadow `&3000-&3FFF` is a copy of main's taken at every game start and the interrupt's variables live below `&3000`. At the game over and completion the main screen is brought up to date and shown before the text. | `src/render.6502`, `irq1_handler`, `wait_for_timer_281a` |
| 24 | 2026-10-16 | **Movers are drawn masked over a saved background** (KC), not EOR'd: each byte `(screen AND mask) EOR pixel` from the game's own mask and pixel tables (the rule the original used for the player only), what was under it kept in a save block per mover per screen and put back when it comes off. Overlapping movers are opaque over each other in slot order, the player on top. The sprites are stored straight (A1, index bytes) in ANDY and bank 4; the run-length mover sprites are gone, which frees `&34D5-&3FFF` for the save blocks. | `docs/step2-layer3.md`, `src/render.6502` |
| 25 | 2026-10-16 | **In play the sound effects are our own 50 Hz driver's** (`src/lib/sfx50.6502`, KC: "really aren't particularly special... closely approximated with a substantially simpler 50Hz sound driver", and reusable): each effect a list of ramps (period and amplitude stepping linearly over N fields), fitted by `tools/sfx50.py` to the MOS's own playing of it (`tools/sfxcapture.mjs`): within a step or two of period and amplitude, sometimes half a field apart. `play_sound` posts a request by chip channel; the vsync interrupt runs the driver with bank 5 paged in. System VIA T1, the MOS's 100 Hz tick, is off in play (TIME stands still), the chip is silenced at the handover each way; the front end's music is the MOS's as before. Interrupts 10.9% of the CPU to 2.2%. | `docs/step2-layer3.md`, `src/lib/sfx50.6502` |
| 26 | 2026-10-16 | **The next pass's logic does not wait for the frame to be shown** (KC; changes decision 18): `wait_for_timer_281a` arms the flip - 2 fields after the last flip, or the next field if that has gone by - and returns; the renderer waits for that flip (`wait_for_flip`) before drawing the next frame, since the hidden screen holds the last one until then. Frames still change only at a vsync and never less than 2 fields apart (25 a second at most), but a pass no longer starts at a vsync: the time a pass used to spend waiting for its slot's end now runs the next pass's logic. Same game: 21.59 to 23.38 passes/s. | `wait_for_timer_281a`, `src/render.6502` |
